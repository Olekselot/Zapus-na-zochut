# Оплата за обличчям

Навчальне демо: людина дивиться в камеру, система перевіряє, що обличчя живе, впізнає клієнта і списує суму з локального рахунку. Чуже фото, роздруківка чи екран телефона оплату не проходять.

Гроші списуються лише після всіх перевірок:

1. у кадрі рівно одне обличчя, кадр різкий, обличчя достатньо велике й дивиться прямо;
2. на всіх кадрах та сама людина;
3. захист від підробки каже «живе»;
4. схожість із шаблоном клієнта не нижча за поріг і помітно вища, ніж з другим найсхожішим клієнтом;
5. для сум понад 500 грн — правильний PIN і суворіший поріг.

Що змінилося і чому — у [docs/CHANGES.md](docs/CHANGES.md). Як збирати дані — у [docs/DATA_COLLECTION.md](docs/DATA_COLLECTION.md). Що ще не зроблено і з чого почати — у [docs/HANDOFF.md](docs/HANDOFF.md).

## Сетап

Потрібен Python 3.12. Команди для PowerShell у Windows, з кореня проєкту:

```text
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
```

Якщо `pip` починає компілювати insightface і падає з помилкою про C++, встановіть Microsoft C++ Build Tools (пункт «Desktop development with C++») і повторіть команду. Точні версії, на яких усе перевірено, лежать у `requirements-lock.txt`.

Перший запуск сам завантажить ваги `buffalo_l` (RetinaFace і ArcFace, ~280 МБ) у `~/.insightface`. Ліцензія цих ваг некомерційна, у звіті це треба згадати. Для порівняння з deepface ставиться `requirements-eval.txt` (тягне TensorFlow), для підготовки CelebA-Spoof — `requirements-data.txt`.
Пакет Topologies не потрібен для застосунку чи рекомендованого навчання. Архітектура `mnv2_scratch` — це MobileNetV2 з torchvision без ваг ImageNet; `topologies_mnv2` залишено для сумісності зі старими вагами.

Тести, без камери й без нейромереж:

```text
python -m unittest discover -s tests -t .
```

## Запуск

```text
python app.py
```

Відкрийте адресу з рядка `Running on local URL`, зазвичай `http://127.0.0.1:7860`. Зупинка — `Ctrl+C`. База рахунків лежить у `data/bank.sqlite`.

Змінні середовища: `CAMERA_INDEX` — інша камера; `ADMIN_PIN` — PIN, без якого кнопку захисту не перемкнути.

## Як користуватись

### Реєстрація

Ім'я, прізвище, баланс, необов'язковий PIN (4–6 цифр) і фото анфас однієї людини: щонайменше 5 придатних, краще 8 і більше. У базу йдуть лише вектори, фото не зберігаються.

- Розмиті фото, фото з кількома обличчями або дуже повернутим обличчям відкидаються. Якщо після цього лишилось менше 5 фото, реєстрація зупиняється з причиною. Якщо на фото різні люди, теж.
- Якщо модель захисту є і ввімкнена, фото екрана чи роздруківки відкидаються.
- Якщо це обличчя вже є в базі під іншим ім'ям, другий рахунок не створюється.
- Якщо ім'я та прізвище вже є, кнопка «Це мій рахунок» з'являється, **лише коли обличчя збігається з цим рахунком**. Інакше можна тільки створити окремий рахунок. Раніше будь-хто, хто знав чуже ім'я, міг додати своє обличчя до чужого рахунку.

### Оплата

- **Оплатити цим фото** — один кадр з вебкамери браузера або файл.
- **Зняти 5 кадрів** — камера комп'ютера, на якому запущено `app.py`.
- **Активна перевірка** — «Нове завдання» показує, що зробити: повернути голову ліворуч чи праворуч або кліпнути. «Виконати завдання і оплатити» пише 3 секунди з камери. Фото таке не повторить, а записане відео не знає, яке завдання випаде.
- Для сум понад 500 грн потрібен PIN клієнта. Після 5 помилок поспіль PIN блокується на 15 хвилин, кожне наступне блокування вдвічі довше (до доби). Правильний PIN скидає лічильник; адміністратор може розблокувати PIN на вкладці «Баланс і журнал» за кодом клієнта.
- Якщо один кадр із серії вибився (інша людина в кадрі, змазаний кадр), оплата йде за більшістю кадрів; якщо узгоджених кадрів не більше половини — відмова «різні люди в кадрах».

Можливі відповіді: оплату проведено; спроба підробки; клієнта не знайдено; неоднозначний збіг (обличчя схоже на двох клієнтів); недостатньо коштів; потрібен/невірний PIN; кілька облич; різні люди в кадрах; поганий кадр; обличчя не знайдено; завдання не виконано; оплату заблоковано (захист увімкнено, а моделі ще немає).

### Баланс і журнал

Кнопка захисту завжди показує справжній стан сервера, також після перезавантаження сторінки. Коли захист вимкнено, на вкладці оплати горить червоний банер. Журнал пише і оплати, і відмови з причиною.

## Навчання

ArcFace не навчаємо. Навчається захист від підробки: класи «живе», «роздруківка», «екран».

```text
python training/train_antispoof.py --smoke                                   # перевірка циклу на CPU
python training/train_antispoof.py --data data/celeba_spoof --balance --test-ratio 0 --epochs 8 --patience 3 --run-name imagenet
python eval/antispoof_metrics.py --data data/celeba_spoof_test --split all   # зовнішній test-набір
python training/train_antispoof.py --data data/celeba_spoof --balance --test-ratio 0 --arch mnv2_scratch --run-name scratch --weights models/antispoof_scratch.pt --meta models/antispoof_scratch_meta.json
python eval/antispoof_metrics.py --data data/celeba_spoof_test --split all --weights models/antispoof_scratch.pt --meta models/antispoof_scratch_meta.json
python training/train_antispoof.py --data data/celeba_spoof data/custom --balance
python training/train_antispoof.py --data data/custom --folds 5 --balance    # крос-валідація за людьми
```

- Модель за замовчуванням — MobileNetV3-Small з вагами ImageNet. Першу епоху вчиться лише голова, потім уся мережа: AdamW, косинусний розклад, згладжування міток.
- На вхід іде квадрат у 2,7 раза більший за обличчя: рамка телефона й край аркуша — найсильніші ознаки підробки. Вузький ArcFace-кроп їх відрізав.
- Аугментації: світло, колір, гамма, масштаб, поворот, JPEG. Сильного розмиття немає, бо воно стирає муар екрана.
- Зберігається найкраща епоха за validation, є рання зупинка.
- Поріг P(live) і температура підбираються на validation. Для CelebA-Spoof цього мало: у дзеркалі немає ID людей, тож validation ділить людей з train і поріг виходить 0. Тому після навчання поріг перепідбирається на людях, яких модель не бачила: `python training/calibrate_antispoof.py --data data/celeba_spoof_test --write`. Половина набору йде на поріг (правило: відхиляти не більше 5 % живих кадрів, пропускати якомога менше атак), друга половина — на звіт; `eval/antispoof_metrics.py` далі ці фото пропускає.
- Метрики на test (люди, яких навчання не бачило) пишуться в метадані моделі, криві навчання — в `eval/results/`. Для порівняння моделей `eval/antispoof_metrics.py` приймає `--weights` і `--meta`; кожен прогін отримує окремий JSON-звіт.
- Підробки з CelebA-Spoof без типу (`spoof/`) вчаться як «друк або екран»: штраф −log(P(друк) + P(екран)).
- Метадані фіксують архітектуру, факт використання ImageNet, найкращу епоху й час навчання для чесного порівняння прогонів.
- Без відеокарти навчання йде на CPU повільно. Для повного навчання є `notebooks/train_antispoof_colab.ipynb`.
- Затримку моделі можна виміряти штучним warm-start через `python eval/latency_benchmark.py --rounds 50 --batch-size 5`.

## Метрики

```text
python eval/recognition_metrics.py                                # LFW: 10 фолдів + усі пари, пише поріг демо
python eval/identification_metrics.py                             # 1:N: галерея з 10/50/100 клієнтів
python eval/antispoof_metrics.py --data data/celeba_spoof --split test
python eval/antispoof_metrics.py --data data/celeba_spoof_test --split all
python eval/antispoof_metrics.py --data data/custom --split all   # перенос на нашу камеру
python eval/embedding_map.py                                      # t-SNE векторів
python eval/compare_deepface.py --per-fold 60                     # потрібен requirements-eval.txt
```

- **Розпізнавання.** На стандартних 6000 парах LFW поріг підбирається на 9 фолдах і перевіряється на десятому. FAR/FRR рахують пари без обличчя як відмову, FMR/FNMR — без них. На 3000 чужих парах не видно FAR нижче ~0,1 % (правило трьох), тому є ще розширений набір: усі пари фото, люди поділені навпіл, тобто мільйони чужих пар. Поріг демо береться звідти для FAR 0,1 %.
- **Ідентифікація 1:N.** Наочно показує, чому оцінка за шаблоном клієнта і відрив від другого кандидата кращі за максимум по всіх фото.
- **Захист.** APCER окремо для друку й екрана; підсумковий APCER — найгірший з них (ISO/IEC 30107-3). Також BPCER, BPCER при APCER 1/5/10 %, DET-крива, матриця помилок. ACER лишаємо лише для порівняння зі статтями.

## Приватність

Усе локально. У SQLite немає фото: лише код клієнта, ім'я, вектори, баланс у копійках, хеш PIN і журнал. Згода на зйомку записується в `data/custom/consent.csv`. Після заліку видаліть `data/`.
