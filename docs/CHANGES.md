# Що змінилося

## Безпека рахунків

| Було | Стало |
|---|---|
| «Це мій рахунок» додавало вектори до рахунку лише за збігом імені. Хто знав чуже ім'я, міг дописати своє обличчя і платити з чужого рахунку | Фото додаються, лише якщо нове обличчя збігається з шаблоном цього рахунку. Перевіряється двічі: при показі кнопки і при натисканні (`src/pipeline.py`, `confirm_existing`) |
| Те саме обличчя можна було зареєструвати під різними іменами | Обличчя, яке вже є в базі, не отримує другого рахунку |
| Реєстрація приймала будь-які фото | Відкидаються розмиті, дрібні, повернуті фото і фото з кількома обличчями; фото різних людей зупиняють реєстрацію; з увімкненим захистом відкидаються фото екрана й друку |
| Кнопка захисту після перезавантаження сторінки завжди показувала «увімкнено», хоча сервер міг бути з вимкненим захистом | Стан кнопки береться з сервера при кожному завантаженні; при вимкненому захисті на вкладці оплати горить банер; можна вимагати `ADMIN_PIN` |
| Без лімітів на суму | Понад 500 грн — PIN (PBKDF2-хеш, блокування після 5 помилок) і поріг схожості +0,10 |
| Баланс як `REAL`, перевірка і списання окремими запитами | Цілі копійки; списання — один `UPDATE ... WHERE balance_kop >= ?` у `BEGIN IMMEDIATE`; старі бази мігрують автоматично |

## Розпізнавання

| Було | Стало |
|---|---|
| Оцінка клієнта — максимум по всіх його фото: що більше фото, то більше шансів у чужого | Косинус до шаблону клієнта (нормований середній вектор) |
| Без перевірки відриву: обличчя, схоже на двох клієнтів, списувало з першого | Статус «неоднозначний збіг», якщо перший кандидат не відривається від другого на 0,05 |
| 5 кадрів усереднювались, навіть якщо на них різні люди | Перевірка, що всі кадри схожі на медоїд групи |
| Поріг підбирався і звітувався на тих самих 1000 парах sklearn LFW `test` | 6000 пар, 10 фолдів: поріг з 9 фолдів, перевірка на десятому |
| «FAR 0,1 %» на 500 чужих парах (тобто «0 помилок») | Правило трьох для роздільності; розширений набір з усіх пар, люди поділені навпіл |
| Пари без обличчя викидались з метрик | FAR/FRR рахують їх відмовою, FMR/FNMR — окремо |
| LFW з sklearn-кропом 125×94 | Повні фото 250×250, обличчя, найближче до центру |
| deepface отримував RGB замість BGR і зовсім інше вирівнювання, ніж ArcFace | Усі моделі бачать той самий вирівняний кроп у BGR, протокол той самий |

## Захист від підробки

| Було | Стало |
|---|---|
| MobileNetV2 з Topologies **з нуля** (у пакеті немає попередньо навчених ваг) | MobileNetV3-Small з вагами ImageNet; Topologies лишився як `--arch topologies_mnv2` для порівняння «з нуля проти донавчання» |
| Вузький ArcFace-кроп без рамки екрана й краю аркуша | Квадрат 2,7× обличчя, без чорних полів |
| Аугментація — лише віддзеркалення | Світло, колір, гамма, масштаб, поворот, JPEG |
| Зберігалась остання епоха | Найкраща за validation, рання зупинка, перша епоха лише голова |
| Ймовірності без калібрування | Температурне калібрування на validation |
| `eval/antispoof_metrics.py` рахував на всій папці, включно з людьми з train | Рахує test-людей з метаданих моделі або весь інший набір (`--split all`) |
| APCER усереднений по всіх атаках | APCER за типами, підсумковий — найгірший; BPCER при APCER 1/5/10 %; DET-крива; матриця помилок |
| `--limit` брав перші фото за алфавітом папок, тобто один клас | Перемішані фото з усіх класів |
| Validation і test по 1–2 людини, один прогін | `--folds K`: крос-валідація за людьми, середнє ± відхилення |
| Лише п'ять кадрів | Активна перевірка: поворот голови в названий бік (за 5 точками) або кліпання (EAR за 68 точками) |
| Ваги завантажувались перед першою перевіркою | `AntispoofModel.warm_up()` завантажує ваги під час `build_demo()`; benchmark не змішує холодний старт із першою оплатою |

## Дані та інструменти

- `tools/prepare_celeba_spoof.py` — збалансована підмножина CelebA-Spoof з дзеркала Hugging Face, шард за шардом.
- `tools/collect.py` — збір власного набору з вебкамери: перевірка якості кадру, manifest, згода.
- `tools/dataset_report.py` — таблиця «людина × клас», чого бракує, дублікати.
- `tools/prepare_lfw_enroll.py`, `tools/enroll_folder.py` — клієнти демо з LFW і пробні оплати.
- `eval/identification_metrics.py` — 1:N на галереях 10/50/100 клієнтів.
- `eval/embedding_map.py` — t-SNE векторів.
- `notebooks/train_antispoof_colab.ipynb` — навчання на GPU в Colab.
- `.github/workflows/tests.yml` — тести на кожен push.
